# 项目实施方案：技术课程深度学习助手（Course RAG Assistant）

> 决策记录：2026-10-18，用户在三个候选 RAG 项目中选择了第 2 个「技术课程深度学习助手」。
> 默认假设（可随时调整）：开发周期 6–8 周；生成模型走 API（效果优先）；第一门课程用《数据挖掘》（已有完整学习笔记，可直接做标注语料）。

## 1. 项目定位（一句话）

一个能「精确引用到页码」的课程 RAG 助手：从你自己的课程资料里找答案、讲先修关联、出题并定位知识盲区；**不知道就承认，不编造**。

## 2. 为什么选它（作品集视角）

- 辨识度：市面上的 PDF 聊天机器人只做「问答」，本项目做「精确引用 + 知识关联 + 学习反馈」三层差异化。
- 数据可得：你手里已有《数据挖掘》详细笔记（Notion 精简版约 8500 字 + 完整版）、吴恩达课程视频笔记、408 复习资料，第一周就有真实语料可用，开发风险低。
- 技术展示面完整：文档解析、混合检索、重排序、引用约束生成、评测体系，一个 RAG 全链路全覆盖。
- 自己能用：408 冲刺期间直接当复习工具，项目和备考互相喂养。

## 3. 范围界定

### MVP 做什么
1. 多格式导入：PDF / PPTX / Markdown，**保留页码与章节信息**（引用的地基）。
2. 混合检索：BM25（抓术语原文）+ 向量检索（BGE-M3，抓同义转述）→ RRF 融合 → BGE Reranker 重排。
3. 约束生成：答案中每个事实性断言必须带「文件名 + 页码」引用；引用对不上的断言被标记或删除；证据不足时明确说不知道。
4. 课程差异化能力（至少做出 2 个）：
   - 精确引用：答案精确到页码和原文段落，附原文预览。
   - 先修知识关联：概念依赖图（如「朴素贝叶斯 → 条件独立 → 贝叶斯定理」），答案自动指出应先复习的前置概念。
   - 跨教材对比：同一概念在不同资料中的定义/符号差异并排展示。
   - 出题 + 错题知识盲区定位：按语料出题，判分后把错题映射到缺失的概念，输出复习清单。
5. 评测体系：自建标注问题集 + 四项验收指标（见第 7 节）+ 消融对比。

### 明确不做（第一版）
- 不做 OCR（扫描版 PDF 暂不支持，先用文字版资料）。
- 不做通用问答：限定课程语料，语料外的问题直接拒绝并说明边界。
- 不接入全部课程：先做透《数据挖掘》一门，再扩展到 408 四科。
- 老师的 PPT 原件不进公开仓库：公开库只放自写示例数据，真实语料放本地 `data/raw/`（已在 .gitignore 排除）。注意版权边界。

## 4. 数据设计

| 层 | 内容 | 来源 | 状态 |
|---|---|---|---|
| 示例语料 | 自写的 3–5 篇短文档（覆盖定义、公式、例子） | 手写 | 第 1 周完成 |
| 真实语料 v1 | 《数据挖掘》精简笔记（Markdown，约 8500 字，章节结构清晰） | 本地已有 | 第 1 周导入 |
| 真实语料 v2 | 数据挖掘完整笔记、吴恩达视频笔记 | 本地已有 | 第 4–5 周导入 |
| 标注问题集 | 60–100 道问答对：问题 + 金标准出处（文件/页码/章节）+ 关键答案点 | 基于真实语料人工标注 | 第 2–4 周分批标注 |
| 不可回答集 | 15–20 道语料外/证据不足的问题（测「承认不知道」） | 人工编写 | 第 4 周 |

标注问题集是本项目含金量最高的资产：它既是评测基准，也是作品集里最有说服力的证据。

## 5. 系统架构

```
课程资料 (PDF/PPTX/MD，保留页码)
   │ ingest.py：抽取 → 清洗 → 按段落切分（chunk 携带 doc/page/section）
   ▼
chunk 存储（id, doc, page, section, concept_tags）
   │ retrieval.py：BM25 + BGE-M3 向量 → RRF 融合 → BGE Reranker 取 top-8
   ▼
answer.py：约束生成 —— 每个断言必须有 [doc, p.N] 引用
   │ 引用校验器：断言文本必须与所引段落实质重叠，否则标记/删除
   ▼
输出：带精确引用的答案 + 「应先复习」先修概念 + 原文预览
   │ evaluate.py：recall@k / MRR / 引用精确率 / 拒答率
   ▼
quiz 模式：按语料出题 → 判分 → 错题映射概念缺口 → 复习清单
```

## 6. 技术选型

| 模块 | 方案 | 理由 |
|---|---|---|
| 后端 | Python + FastAPI | 生态成熟，作品集主流 |
| 文档解析 | PyMuPDF（PDF）、python-pptx | 页码保留能力强 |
| Embedding | BGE-M3 | 中文检索强，本地 CPU 可跑 |
| 向量库 | PostgreSQL + pgvector（或 Qdrant） | 够用即可，先 pgvector |
| 混合检索 | BM25 + 向量，RRF 融合 | 术语原文与同义转述都要抓 |
| 重排序 | BGE Reranker（m3/v2-m3） | 中文重排效果好 |
| 生成模型 | OpenAI 兼容 API，可替换 | 先保证效果；BGE 可本地跑兼顾隐私 |
| 评测 | 自建标注集 + 脚本 | 核心验收证据 |

## 7. 验收标准（四项，缺一不可）

1. **检索准确**：在标注集上，真正相关的条款/段落能被找到，而不是只找到词语相似的段落。指标：recall@8、MRR。
2. **引用可靠**：引用的出处真实存在，原文与断言匹配，适用于当前问题。指标：引用精确率（人工抽查 + 自动文本重叠校验）。
3. **知道何时说不知道**：证据不足、语料未收录时明确说明，不编造。指标：不可回答集上的拒答率，误答率趋近 0。
4. **优于基线**：固定测试集上对比「纯向量检索 / 混合检索 / 混合+重排」三档，给出消融对比表并分析失败案例。

## 8. 开发里程碑（6–8 周）

- **第 1 周**：ingest 落地。三种格式解析器 + 按段切分 + 页码/章节元数据；示例语料入库；CLI 可打印 chunk。
- **第 2 周**：检索落地。BGE-M3 embedding + pgvector 建库；BM25 索引；RRF 融合；标注问题集完成 30 道。
- **第 3 周**：重排 + 约束生成。BGE Reranker 接入；答案生成 prompt（含引用格式）；引用校验器 v1。
- **第 4 周**：评测体系。标注集补到 60–100 道 + 不可回答集；evaluate.py 跑通四项指标；第一份消融对比报告。
- **第 5 周**：课程差异化（一）。精确引用 UI/API + 原文预览；概念依赖图 v1（先修关联）。
- **第 6 周**：课程差异化（二）。跨教材对比；quiz 出题 + 判分 + 错题→概念缺口映射。
- **第 7–8 周**：硬化与展示。修评测暴露的问题；写 README 架构说明；录 demo；整理「失败案例分析」文档（面试谈资）。

## 9. 风险与对策

| 风险 | 对策 |
|---|---|
| BGE 模型本地下载慢/代理不稳 | 先用 API 版 embedding（如硅基流动兼容接口），本地版作为可选项 |
| 切分破坏公式/表格语义 | 公式块整体保留为一个 chunk；表格转 markdown 保留结构 |
| 引用校验误杀正确引用（转述） | 校验分两级：文本重叠（严）+ LLM 语义判断（宽），只删两级都不过的 |
| 标注问题集耗时 | 分批标注，先 30 道跑通链路；标注即复习，一举两得 |
