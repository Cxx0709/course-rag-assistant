# 回答完整性改进 v9

## 改动

完整解释有时已在前 50 个检索候选中，但排名较低，无法进入最后用于回答的三个片段。
例如，多层感知机的完整结构定义位于候选第 14 位；训练集与测试集用途的概括位于第 12 位。

新增可选 `ChatReranker`：使用已有聊天模型从前 24 个候选中选择最能直接回答问题的段落，再按既有流程选择原文句子并附加引用。
这是聊天模型段落选择，不是 BGE 重排；原有 BGE 接口保留，尚未配置的 BGE 服务仍单独记为未运行。

段落选择只接受请求内的 `passage_ids`，不能改写文本、编造来源或引用未提供的候选。
错误编号、重复编号、额外字段、截断 JSON 或服务异常会回退到原排序，并在评测中记录；空数组表示没有合适的段落。
非空选择会优先排列选中段落，再用未选中的原始候选补足 top-k，避免一次模型遗漏导致所有可用证据消失。
每个候选最多提供 800 字符的首尾摘录，完整原文仍用于最终引用校验。中部省略可能遗漏证据，不能保证选到所有正确段落。

在聊天模型重排模式下，对于“某概念的结构／组成／工作原理是什么”这类标准问法，证据覆盖检查以概念名称为主，不要求正文重复“核心结构”等问法。
个人记录来源、字段缺失、记录冲突及引用校验继续执行。
新模式的句子选择提示要求覆盖问题的组成部分，并尽量减少重复定义、例子和背景文字。最终按来源优先级排列选中的句子，最多保留六句；这不能证明语义完整，较复杂的问题仍可能缺少细节。
未启用该模式时保留原有选句提示和证据规则。另修复英文括号术语在 PDF 中换行时被显示为两个半句的问题。

## 使用

先启动已有的本机 Ollama，并设置：

```powershell
$env:NO_PROXY = '127.0.0.1,localhost'
$env:COURSE_RAG_OLLAMA_MODEL = 'bge-m3:latest'
$env:COURSE_RAG_OLLAMA_CHAT_MODEL = 'qwen3.5:9b'
$env:COURSE_RAG_OLLAMA_CHAT_THINK = 'false'
$env:COURSE_RAG_OLLAMA_CHAT_NUM_PREDICT = '512'
$env:COURSE_RAG_OLLAMA_CHAT_NUM_CTX = '16384'
$env:COURSE_RAG_OLLAMA_CHAT_TIMEOUT = '120'
.\.venv\Scripts\python.exe -X utf8 -m course_rag_assistant answer "多层感知机的核心结构是什么？" --data data/raw/datamining-notes --chat-rerank
```

`--chat-rerank` 是显式启用开关，会增加一次模型调用。未配置聊天模型时明确报错。
`num_ctx` 是 Ollama 的上下文窗口参数，见 [官方参数说明](https://docs.ollama.com/modelfile#valid-parameters-and-values)。
此处显式设为 16384，以容纳更大的候选集合；更大窗口会增加资源占用。默认不设置该变量时，沿用服务端配置。

同配置对比是否启用聊天模型段落选择：

```powershell
.\.venv\Scripts\python.exe -X utf8 scripts/evaluate_quality.py --dense --chat --chat-rerank --modes hybrid hybrid+chat-rerank --output eval/reports/quality-v9-chat.json
```

新报告同时记录段落选择的模型原始返回、选中编号、候选来源、耗时和回退次数。它与答案生成的调用统计分开，不能把重排失败后的原排序当成成功重排。

当前仍使用原 30+10 题开发集。题目、参考页和答案点没有因本轮改进而修改；独立人工复核仍未完成。

## 最终实测

报告：[quality-v9-chat.json](../eval/reports/quality-v9-chat.json)。两种模式使用相同的 `qwen3.5:9b`、16384 上下文窗口、512 输出预算，以及同一份语料、向量、查询缓存和题目。
新模式同时包含段落重排、选句提示和结构类问法的证据检查调整，表中差异不能归因于重排单一因素。

| 指标 | 本轮普通 hybrid | 本轮 hybrid + chat-rerank |
| --- | ---: | ---: |
| 前 8 个结果命中参考页 | 83.33% | 96.67% |
| MRR@8 | 0.6281 | 0.7983 |
| 字面答案点覆盖率 | 75.00% | 85.28% |
| 参考页引用精度 | 58.54% | 50.41% |
| 可回答题被拒答 | 0 / 30 | 0 / 30 |
| 不可回答题被拒答 | 10 / 10 | 10 / 10 |
| 整轮评测耗时 | 45.46 秒 | 164.22 秒 |

新模式共调用段落选择 40 次，无异常回退；两种模式各有 30 次答案生成，均无生成失败或整条答案被引用校验拒绝。耗时来自本机单次运行，不代表稳定延迟。

“多层感知机”现在包括隐藏层和激活函数；“训练集与测试集”现在直接说明拟合参数与评估模型；“自动微分”现在包含计算图和反向传播。完整实测输出见 [回答示例](answer-examples-v9.md)。
首轮因候选筛选过度而拒答的“张量”问题，在保留候选后恢复正常；首轮报告保存在 [quality-v9-chat-first-pass.json](../eval/reports/quality-v9-chat-first-pass.json)，不作为最终结果。

答案点覆盖率衡量字面匹配，不等于语义正确率。参考页引用精度下降说明引用更分散；即使句子确实来自教材，也不能据此认定它与问题相关。部分答案仍重复定义，需要进一步改善简洁性。当前结果支持把新模式作为可选功能，不能宣布质量验收完成。

代码验证：152 项测试通过，修改的 Python 文件通过 Ruff 检查；v4、v5 两组既有回归各 20 / 20 通过。离线评测另存 [quality-v9.json](../eval/reports/quality-v9.json)，混合检索命中率仍为 83.33%。与旧 v8 报告的比较还受到模型上下文配置差异影响，因此上表采用本轮同配置对比。
