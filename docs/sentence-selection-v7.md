# 原文句子编号选择 v7（2026-10-25）

## 结果

本轮修复 v6 实测发现的生成与引用衔接问题：模型只返回原文句子编号，程序取回对应原文并附加来源，然后继续执行原有引用校验。
相同的 30 道可回答题与 10 道不可回答题、语料、向量索引、问题向量以及模型配置均通过哈希或配置对比确认未变。
题集仍是开发集，没有独立人工验收或新的留出集。

| 指标 | v6 聊天模型 | v7 编号选择 | v7 离线摘录 |
|---|---:|---:|---:|
| 混合检索 Recall@8 | 80.00% | 80.00% | 80.00% |
| 可回答题最终拒答 | 30/30 | 0/30 | 0/30 |
| 答案点字面覆盖 | 0.00% | 73.33% | 57.78% |
| 参考页码引用精确率 | 无有效引用 | 60.49% | 56.31% |
| 不可回答题最终拒答 | 10/10 | 10/10 | 10/10 |
| 模型调用次数 | 30 | 30 | 0 |
| 模型异常回退次数 | 0 | 0 | 0 |

v7 的 30 次返回全部通过编号解析和后续引用校验，没有无效编号拒答，也没有模型主动空选。
10 道反例仍在前置证据筛选阶段拦截，未调用模型；不能用它们证明模型自身的拒答能力。
当前配置为本机 `qwen3.5:9b`、关闭思考、`num_predict=512`、请求超时 60 秒；单次评测阶段约 39.09 秒，v6 为 86.93 秒。
模型加载和缓存状态可能影响耗时，不能据单次运行推广速度结论。

报告：`eval/reports/quality-v7-chat.json`；离线三个检索模式报告：`eval/reports/quality-v7.json`。
本轮没有覆盖历史 v6 报告，也没有自动提交代码。

## 实现契约

1. 先按现有规则筛选证据，缺少来源、所问值或出现冲突时仍直接拒答。
2. 对最多三个可用片段的原文句子按顺序分配从 1 开始的请求内编号。提示词提供问题和每个编号对应的文本及来源。
3. 模型只输出 `{"sentence_ids":[1,3]}`。程序不显示模型撰写的答案或模型提供的引用。
4. 验证唯一字段、整数类型和编号范围。布尔值、浮点数、字符串编号、越界编号、额外字段、重复 JSON 字段、尾随文本和截断 JSON 均拒绝；混合有效与无效编号也整体拒绝。
5. 允许完整包裹 JSON 的代码围栏；重复选择的编号去重，保留选择顺序。空数组表示模型主动拒答。
6. 程序从本次候选表取出选中句子并附加对应页码或章节引用，再执行原有完整原句校验。资料中伪造的引用字符串不能绕过该校验。

服务或生成器异常仍按既有行为回退至摘录，并在评测中记录失败。
编号解析失败发生在服务异常回退分支之外，不会被悄悄替换成成功的摘录答案。

新拒答原因：`invalid_sentence_selection`（输出格式或编号无效）、`model_abstained`（模型返回空数组）。
`CitedAnswer` 和批量问答 JSON 新增 `selected_sentence_ids`，评测及复核材料同时保存这些编号。
评测中的 `model_abstentions` 单独记录模型主动拒答；`model_outputs_fully_rejected` 统计校验失败，不再把空选计入格式失败。

自定义 `TextGenerator.generate()` 的返回契约改为上述 JSON，原有直接返回答案文本的自定义生成器需要适配。
离线调用方式和 `CitedAnswer` 原有位置参数保持兼容；HTTP 请求参数与模型服务配置保持不变。

## 尚未解决的答案质量问题

引用文本真实、编号合法不意味着选中的内容能完整回答问题。例如：

- `d2l-v2-07` 问多层感知机核心结构，模型选到了目录中的章节名称。引用可追溯，但没有解释核心结构。
- `d2l-v2-27` 问一般小批量训练步骤，选择的证据来自多 GPU 并行训练，范围与问题未必吻合，需要人工复核。
- `d2l-v2-14`、`16`、`19` 的字面答案点没有命中，但答案含相关定义或解释。关键词指标不能直接当成事实正确率或错误率。

73.33% 是字面答案点覆盖，60.49% 是相对于所选参考页码的引用精确率，两者都不是语义正确率。
本次解决的是模型输出格式和来源衔接，不支持自由改写、推理解释或通用事实验证。
下一步应改善目录等非正文证据的处理，并针对失败案例开展独立人工复核；真实 BGE 重排验收仍需可用服务。
